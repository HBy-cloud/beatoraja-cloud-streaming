## ADR-007 — D:에 VFS 캐시 배치

- 날짜: 2026-10-31
- 상태: 채택(이번 M0 실험 설정; 장기 운영 검증 전)
- 배경 및 문제: 마운트 전 C: 여유 29.1GiB, D: 여유 222.9GiB(NTFS, Healthy). SSD 공간 보호가 최우선.
- 검토한 선택지: C: 캐시와 D: 전용 캐시 경로.
- 결정 및 이유: `D:\BMS-Cloud\cache`를 사용하고 `--vfs-cache-max-size 30G`, `--vfs-cache-min-free-space 100G`를 설정. 상대적으로 여유가 큰 D:를 선택.
- 안전·용량·성능 영향: 30G는 절대 상한이 아니며 100GiB 여유도 항상 보장되지 않음. 실험 후 사용량 미측정.
- 검증 방법 및 결과: D: 사전 상태와 마운트·재생 성공 확인; 캐시 실점유량과 사후 여유 미검증.
- 관련 문서/커밋: `PROGRESS.md` 2026-10-31 M0 기록. 이번 변경의 커밋 미확인.

## ADR-008 — 압축 직접 실행 관찰을 계획보다 앞당김

- 날짜: 2026-10-31
- 상태: 채택(실험 순서에 한정; ZIP 기본안 채택 아님)
- 배경 및 문제: Altale 압축 해제 폴더 업로드에 시간이 오래 걸려 초기 폴더 검증 범위를 줄일 필요가 있었음.
- 검토한 선택지: 폴더 여러 곡 업로드 후 계획대로 ZIP 비교 / 폴더 1곡 우선 확인 후 ZIP 실행 관찰.
- 결정 및 이유: 사용자 요청으로 폴더 우선 검증을 1곡으로 축소하고 ZIP 관찰을 앞당김.
- 안전·용량·성능 영향: 원본 압축 파일 삭제·변환 없음. ZIP의 성능 우위나 대규모 전환은 결론 내리지 않음.
- 검증 방법 및 결과: ZIP 재생 가능 사용자 보고만 있음. 실제 ZIP·채보 경로, 로딩 시간, 소리·BGA 세부 검증 미확인. M4 A/B 비교 완료 아님.
- 관련 문서/커밋: `PROGRESS.md` 2026-10-31 M0 기록.

## ADR-009 — 이번 M0에서 DB·설정 백업 생략

- 날짜: 2026-10-31
- 상태: 일회성 예외 기록(영구 정책 변경 아님)
- 배경 및 문제: beatoraja 경로 추가 및 DB 업데이트 전에 백업하는 것이 기존 안전 원칙이나, 사용자가 이번 시험에서 생략을 요청함.
- 검토한 선택지: 백업 후 시험 / 사용자 요청에 따라 이번에만 백업 생략.
- 결정 및 이유: 사용자 요청에 따라 이번 시험에서 백업을 생략한 사실을 기록함.
- 안전·용량·성능 영향: 변경 전 복구 지점 미확보 위험. `AGENTS.md`와 `SPEC.md`의 향후 백업 원칙은 변경하지 않음.
- 검증 방법 및 결과: 백업 및 복구 검증 모두 미실행. 백업 완료로 표시하지 않음.
- 관련 문서/커밋: `PROGRESS.md` 2026-10-31 M0 기록.

## ADR-010 — 최초 로딩 지연으로 추가 실험·개발 중단

- 날짜: 2026-10-31
- 상태: 채택(현재 시점 작업 중단; 설계 폐기 아님)
- 배경 및 문제: 폴더 곡 첫 관찰 로딩 60초 이상, 곡 미확인 별도 사례에서 7분 초과 보고. 재선택은 빠르지만 원인과 성능 통계 미측정.
- 검토한 선택지: 즉시 병목 측정·Java prewarm 개발 진행 / 현재 결과만 기록하고 중단.
- 결정 및 이유: 사용자 판단으로 추가 개발·성능 실험을 중단. 현재 구성은 최초 로딩 지연으로 실사용성이 부족하다는 잠정 평가.
- 안전·용량·성능 영향: 15초 목표는 유지하되 달성했다고 주장하지 않음. M0 부분 검증, M1~M6 미완료. 마운트 종료·캐시 정리 여부 미확인.
- 검증 방법 및 결과: 재생 가능과 지연 사례는 사용자 관찰에 근거; p50/p95·실패율·전송량·캐시 점유량은 미측정.
- 관련 문서/커밋: `PROGRESS.md` 2026-10-31 M0 기록. 재개 시 첫 작업은 느린 곡 1개의 정확한 경로·저장 형태 확인 후 전송량과 로딩 병목 측정(이번에는 실행하지 않음).
