# Architecture Decision Records (ADR)

> 프로젝트: beatoraja Cloud VFS Streaming  
> 기준 문서: [`SPEC.md`](SPEC.md) (v3)  
> 최초 작성: 2026-10-31

이 문서는 **이미 합의한 설계 결정**과 향후 변경 이유를 기록한다. 성능 수치와 프로그램 호환성은 실측·검증 전까지 가정으로 구분한다. 결정 변경 시 기존 기록을 지우지 말고 새 ADR을 추가한다.

## 결정 목록

| ID | 제목 | 상태 | 근거 |
|---|---|---|---|
| ADR-001 | 로컬 용량 절약 우선 | 승인 | SSD 500GB 중 여유 약 300GB, 예상 BMS 라이브러리 500GB 초과 |
| ADR-002 | 읽기 전용 rclone VFS 마운트 | 채택 · M0 검증 전 | 원본 보존, beatoraja 변경 최소화 |
| ADR-003 | 캐시 30GiB로 시작 | 채택 · 조정 가능 | SSD 사용량 최소화, 50GiB는 실험 후 결정 |
| ADR-004 | 로딩 15초는 목표이지 보장이 아님 | 승인 | Google Drive의 실제 요청 지연 및 곡별 자원량 미측정 |
| ADR-005 | Java CLI는 측정 뒤 도입 | 채택 | 불필요한 자동화보다 최소 검증 우선 |
| ADR-006 | ZIP 직접 실행은 비교 실험 | 검증 대기 | 설치된 beatoraja 버전의 ZIP 기능 확인 필요 |

## ADR-001 — 로컬 용량 절약 우선

- **결정:** 클라우드 원본을 로컬에 일괄 복제하지 않는다. SSD 캐시는 한정적으로 사용한다.
- **이유:** 원하는 곡의 총량이 SSD 전체 용량을 넘을 것으로 예상된다.
- **영향:** 미캐시 곡에는 네트워크 지연이 발생할 수 있다. 속도 개선보다 디스크·데이터 안전을 우선한다.
- **검증:** 실제 캐시 점유량과 SSD 여유 공간을 기록한다.

## ADR-002 — 읽기 전용 rclone VFS 마운트

- **결정:** `Google Drive → rclone mount --read-only --vfs-cache-mode full → WinFsp → B:\ → beatoraja`를 기본 후보로 사용한다.
- **이유:** 기존 게임의 곡 파일 접근 방식을 크게 변경하지 않고 캐시를 활용하기 위함이다.
- **안전 조건:** Google Drive 원본 자동 삭제·이동·덮어쓰기를 금지한다. beatoraja 설정과 DB는 로컬에 두며, 변경 전 백업한다.
- **검증:** M0에서 곡 5~10개 플레이, 원본 읽기 전용 동작, 로그 확인. 실제 성공 전에는 '작동 완료'로 기록하지 않는다.

## ADR-003 — 초기 캐시 30GiB

- **결정:** rclone 캐시 설정을 처음에는 30GiB로 시작하고, 측정 후 50GiB 확장을 판단한다.
- **이유:** SSD 공간 절약이 최우선이다.
- **주의:** rclone 캐시 상한은 순간적인 디스크 점유량의 절대 보장이 아니다. SSD 가용 공간 100GiB 이상 보호를 목표로 하고, 강제 캐시 파일 삭제 도구는 만들지 않는다.
- **검증:** M0~M3에서 할당량과 여유 공간을 관찰한다.

## ADR-004 — 미캐시 로딩 15초 목표

- **결정:** 플레이 시작 요청부터 플레이 화면 준비까지의 시간을 측정한다. 미캐시 15초 이내는 최적화 목표이며 SLA가 아니다.
- **이유:** 속도 테스트의 365Mbps는 Google Drive 실측이 아니며 곡별 키음 파일 수에 따라 차이가 클 수 있다.
- **검증:** M1에서 20곡 이상, 미캐시/재로딩/prewarm 구분, 중앙값·p95·실패율·15초 이내 비율 기록.

## ADR-005 — 단계별 Java CLI 개발

- **결정:** M0 마운트와 M1 측정 후 M2 목록 기반 prewarm을 만들며, 디스크·오류 가드는 M3, DB 자동 선정은 M5에 둔다.
- **이유:** 초기 병목이 확인되기 전 불필요한 기능·복잡성을 늘리지 않기 위함이다.
- **검증:** 모듈마다 JUnit 테스트, 실행 결과와 미검증 항목을 `PROGRESS.md`에 남긴다.

## ADR-006 — ZIP은 기본안이 아닌 실험

- **결정:** 원본 폴더 구조를 유지하며 시작한다. ZIP 직접 실행은 M4에서 일부 곡을 대상으로 A/B 비교한다.
- **이유:** ZIP 기능은 설치된 beatoraja 버전에서 호환성과 성능을 확인해야 한다.
- **제약:** 전체 BMS 라이브러리의 일괄 ZIP 변환이나 원본 삭제를 초기 범위에 포함하지 않는다.
